# 0.3.1 theme and contrast correction

## Root cause and changes

The Mantine PostCSS transform expanded `light-dark()` inside `:root` into a descendant selector that could not match the document root. Mantine controls switched to dark colors while the application background stayed light. Root surfaces now use explicit theme selectors.

Public login and invitation pages expose Light, Dark and System choices. A guest's theme survives reload and navigation; signed-in account preferences remain server-backed. Only the guest theme is stored locally, never another account's accent or credentials. A direct invitation URL starts its auth query so controls do not remain pending. Failed invitations show a localized inline error without discarding input; success clears the submitted form.

Secondary text, placeholders, links, keyboard focus and input boundaries use scheme-aware colors. Chart and progress fills have a separate contrast pair instead of reusing the filled-button shade, including very dark or very light custom accents. Semantic status colors remain distinguishable from the neutral track.

## Verification

The original dark-background failure, disabled direct-invite picker and invisible black progress ring were reproduced by failing browser regressions before their fixes. The checks inspect computed colors and interactions, not source text.

The broader browser suite passed 73 scenarios; web unit tests passed 76 cases. A dedicated 15-scenario suite verifies the production bundle: light/dark/system, persisted guest selection, RU/EN, keyboard switching, 390/1440px layouts, default/black/white accents, catalog viewer/editor surfaces, invitation errors and graph contrast. It is now included in CI after the build. Text/placeholder checks require 4.5:1, input boundaries and progress graphics require 3:1 for the sampled elements; this is not a whole-application accessibility certification.

Build, TypeScript and independent UI/security/operations/hygiene review passed. No database schema, server authorization or project content changes are included. The schema remains 5; the previous schema-5 app is an app-only rollback option. Existing installation limitations in the 0.3.0 report remain unchanged.
