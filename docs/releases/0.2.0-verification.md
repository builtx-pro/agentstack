# 0.2.0 repository integration verification

Verified on 2026-11-05 using Node.js 22, PostgreSQL 18, Chromium and Docker Compose. This records observed checks, not a coverage percentage or security certification.

## Automated checks

75 server/API/provider tests, 49 frontend unit tests, 38 CLI tests, 32 SDK tests, 9 MCP tests, 6 setup checks, 7 migration checks and 32 Playwright browser scenarios passed. Build, TypeScript and the production dependency audit passed. Independent security, database, testing, operations and publication reviews passed after the findings were corrected.

The tests include revoked credentials or membership during a paused provider read, three-table tenant isolation with positive controls and denied writes, immutable snapshots, concurrent web/source conflicts, a 600-object apply, bounded streams/deadlines/concurrency, ADR lifecycle vocabulary and partial-clone lazy-fetch prevention. CI fixture processes explicitly exclude the outer runner's branch identity.

## Actual integration and deployment

- A browser fetched committed epics from the public engine repository, reviewed and applied the hierarchy, and displayed its pipeline summaries and source bindings. The deployed run imported 96 related records and five provider pipeline summaries.
- The CLI read eight committed ADR files: dry run created no snapshot; explicit stage created a reported snapshot without applying objects.
- A private source repository's actual GitHub Actions run succeeded with a dedicated read/write project token and a pinned engine SHA. The API contained the exact pushed commit and five proposed documents/rules. Human application remained pending; CI did not activate rules or accept feedback.
- The deployed API reports schema 4. An actual post-upgrade production backup was restored to a separate local database; object/file/note counts, repository bindings and `pg_amcheck` passed. The encryption key was backed up separately with protected deployment configuration.
- All original legacy static files matched their previous hashes. Screens, illustrations, presentation dependencies, 3D resources and existing comment/history records were preserved. No legacy API writes were re-enabled.
- A scoped stdio MCP connection discovered 20 tools, saw only its authorized project and read repository/context/review data without mutations.
- A fresh authenticated catalog load completed with 12 object requests and no background catalog reload loop. This is a single deployment observation, not a performance guarantee.

## Boundaries

GitHub.com and GitLab.com are supported; self-hosted providers and OAuth installation flows are not included. Private credentials were tested through synthetic provider responses; no production private Git provider token was required for the CI mode. GitLab was covered by connector tests, not a live private pipeline deployment.

Provider reads run on explicit refresh or CI requests. Visible pipeline widgets refresh cached API data; they do not continuously query Git hosts. GitLab's `.post` job may still observe its own pipeline as running until a later refresh. Web edits are not pushed back to Git. Missing source files never delete workspace records. Customer pipeline sharing is opt-in and excludes source URLs and commits.
