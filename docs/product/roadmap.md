# Roadmap and execution sprints

No calendar estimates. A sprint is an ordered implementation batch, not a promised duration.

| Wave | Sprint | Outcome | Epics |
|---|---|---|---|
| M1 | S01 | Safe foundation, access and history | 001–003 |
| M2 | S02 | Screens, assets and review loop | 004–006 |
| M3 | S03 | Knowledge, delivery planning and agent adapters | 007–009 |
| M4 | S04 | Dashboards, migration and public release | 010–012 |
| M5 | S05 | Repository connections, reviewed plan/docs sync and pipeline visibility | 013 |
| M6 | S06 | Ordered catalogs, personal accounts, illustrated UI and guided installation | 014 |

All requested capabilities remain in scope. Optional later extensions: SSO, customer subdomain aliases, CI attestation providers, remote OAuth MCP. These must not block the stdio MCP or authenticated customer workflow.

Implementation must finish with migration verification; publishing an incomplete skeleton does not satisfy this request.

M5 is an additional requested implementation batch. Provider refresh and CI stage changes; human application and conflict review remain explicit. See [repository integration](repository-integration.md).
